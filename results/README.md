# Canonical paper results

This directory pins the numbers reported in the paper
(*HELM: Compiler-Guided Heterogeneous Execution for Large Language Models on
Memory-Constrained Systems*) in machine-readable form, together with a
validator that (a) proves the committed numbers are internally consistent and
(b) compares fresh benchmark runs against them.

## Layout

| File | Paper element |
|---|---|
| `paper/table2_decode_throughput.csv` | Table II — decode throughput (tok/s) / TTFT p50 (s) for HELM, Accelerate, DeepSpeed ZeRO-Inference and vLLM across 3 GPUs x 10 models (22 feasible rows), output length 128, batch = 1 |
| `paper/table3_llamacpp_comparison.csv` | Table III — HELM vs. llama.cpp manual `--n-gpu-layers` sweep (Llama-2-13B, RTX 3090) |
| `paper/table4_kv_page_size.csv` | Table IV — decode throughput vs. KV page size with paging active |
| `paper/fig4_ttft_prompt_scaling.json` | Fig. 4 — TTFT vs. prompt length (Qwen3-32B, RTX 3090, cpu(43u)+cuda(23u)) |
| `paper/fig5_max_output_tokens.json` | Fig. 5 — maximum supported output length per backend |
| `paper/fig6_paging_throughput.json` | Fig. 6 — decode throughput vs. context with KV paging (Mistral-Nemo-12B, RTX 3090) |

Cell conventions in the CSVs: `OOM` = weight-load out-of-memory,
`FAIL_INIT` = backend initialization/compile failure (the paper's `x` symbol).
Fig. 5 cells the paper reports only graphically are marked `NOT_REPORTED`
rather than guessed.

## Provenance

The values in `paper/` are transcribed from the published paper (tables
verbatim; figure values from the figure axes/labels and caption text) — they
are the numbers reported in the paper, measured on the paper's three testbeds
(Section V-A; all RTX 3090 rows on the EPYC 7H12 host).

Three provenance tiers exist in this repository, in decreasing strength:

1. **CI-validated cells** — committed raw runs reproduce the Table II cell
   mechanically in CI: the RTX 4060 rows
   (`experiments/results/rtx4060_in128_rerun/`). Independent-hardware
   reproductions live in `experiments/results/rtx3090_9900x_repro/`
   (e.g. the RTX 3090 / Qwen3-14B vLLM weight-load `OOM` cell, reproduced
   on a different 3090 host).
2. **Paper-transcribed cells** — the remaining `paper/` values; raw sweeps
   for these were produced on rented/lab GPU hosts and are regenerated by
   the drivers in `experiments/` (see `REPRODUCING.md`).
3. **Historical development artifacts** — files like
   `experiments/results/rtx_3090_helm_*_ablations.json` and
   `experiments/results/20260316_160248/` predate the paper's
   final measurement campaign and were taken on different hosts, thread
   counts, or code revisions. Where they differ from `paper/` (e.g. earlier
   Qwen3-14B RTX 3090 numbers around 7.3-7.8 tok/s vs. the paper's 8.1),
   the `paper/` values are the ones the paper reports; the historical files
   are kept as provenance of the development process, not as canonical
   results.

## Validating

```bash
# 1. Internal consistency (no GPU, no dependencies beyond the stdlib):
python results/validate_results.py

# 2. Render the tables as Markdown:
python results/validate_results.py --print

# 3. Compare a fresh benchmark run against Table II:
python results/validate_results.py \
    --check-run experiments/results/<run>/paper_results.json \
    --gpu "RTX 4060" --model Qwen3-4B
```

The self-check recomputes every derived claim from the raw cells: per-row
speedups (within one-decimal rounding bounds), the **6.2x geometric-mean**
decode-throughput improvement over the nine overflow configurations, the
**5.9x geometric-mean / 256x maximum** context extension, Fig. 6 paging
monotonicity, Fig. 4 TTFT scaling (20.8x), Table III (auto partition beats
every manual fp16 split), and Table IV page-size monotonicity.

The `--check-run` mode understands the `paper_results.json` schema produced
by `experiments/paper_bench.py` (Table II throughput = `1000 /
decode_lat_p50`; TTFT is stored in milliseconds). The default tolerance is
+/-25% because absolute throughput on overflow models tracks the host
CPU/DRAM of the machine (paper Section VI-E); on hardware matching the
paper's testbeds it can be tightened, e.g. `--tolerance 0.1`.

Example against the committed RTX 4060 raw run:

```bash
python results/validate_results.py \
    --check-run experiments/results/rtx4060_in128_rerun/Qwen-Qwen3-4B/helm/A_latency/paper_results.json \
    --gpu "RTX 4060" --model Qwen3-4B
# decode throughput 18.82 tok/s within +/-25% of paper 18.8 tok/s   [ok]
# TTFT p50 0.340 s within +/-25% of paper 0.34 s                    [ok]
```
